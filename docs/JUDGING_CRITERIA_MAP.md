# Judging Criteria Map

| Criterion | CXOS evidence |
| --- | --- |
| Innovation | Full CX signal-to-action loop rather than another isolated support chatbot. |
| Technical depth | React/TypeScript client, Express API, OpenAPI-generated hooks and Zod schemas, PostgreSQL state and audit. |
| Impact | Risk prioritization, root-cause themes, journey friction and measurable-looking metrics with explicit demo-only caveats. |
| UX | Shared inbox/customer context, responsive navigation, filters, loading/error states, theme toggle and clear human approval points. |
| Feasibility | A focused rescue workflow with deterministic demo behavior and a defined path toward provider/connectors. |
| Scalability | Contract-first API and separated persistence/service boundaries; production tenant isolation remains a prerequisite. |
| Security and responsible AI | Synthetic-only dataset, blocked prompt-injection fixture, bounded inputs, no model agency, evidence/limitations, human approval and audit. |
| Presentation | Three-minute Sarah Williams narrative and 30-second pitch in `DEMO_SCRIPT.md`. |
